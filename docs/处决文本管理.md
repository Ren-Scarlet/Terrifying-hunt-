# 处决文本与 QTE 管理

这套系统把「处决写什么文本」和「QTE 怎么接入」都从代码里拆了出来。日常加文本只改 CSV，不用改 TypeScript。

## 1. 文件在哪

| 文件 | 作用 |
| --- | --- |
| `data/execution-texts.csv` | **你维护的源文件**，Excel / WPS 可直接打开 |
| `src/game/data/executionTexts.json` | 脚本生成，游戏实际读取；不要手改 |
| `scripts/execution-texts.mjs` | 导入 / 导出 / 校验脚本 |
| `src/game/execution/` | 解析与演出模块 |
| `src/ui/qte.ts` | 通用 QTE 输入系统 |

## 2. CSV 列

| 列 | 说明 |
| --- | --- |
| `id` | 唯一 id，例如 `site_fridge_02`、`victim_meg_01` |
| `kind` | `normal` 普通处决 / `special` 地点处决 / `qte` QTE 处决 / `any` 通用 |
| `site` | 地形：处决点 id（`fridge`、`microwave`…）或房间 id（`kitchen`…），留空不限 |
| `killer` | 杀手名，例如 `迈克尔·迈尔斯`；留空不限 |
| `victim` | 幸存者 id 或中文名，例如 `meg_thomas` 或 `梅格·托马斯`；留空不限 |
| `when` | 仅 QTE 用：`success` 成功 / `fail` 失败；留空表示两种结果通用 |
| `weight` | 同优先级文本的随机权重，默认 `1`；填 `3` 就比 `1` 更容易抽到 |
| `title` | 处决标题（大字） |
| `line` | 角色台词（斜体小字），可留空 |
| `description` | 处决描述（正文） |

文本里可以用占位符：

- `{victim}` → 受害者名字
- `{killer}` → 杀手名字
- `{site}` → 地形名（如「冰柜封存」）

例：

```csv
victim_meg_fridge,special,fridge,,梅格·托马斯,,2,最后一次躲藏,别怕，很快就好。,你把她按进冰柜时，她还在小声数着数。
```

这条只会对「梅格·托马斯 + 厨房冰柜」生效，权重 2。

QTE 成功 / 失败可以分开写：

```csv
qte_meg_success,qte,,,,success,1,完美的节拍,你偏偏踩准了。,她在最后一刻睁开眼睛，却只看见你落下的手。
qte_meg_fail,qte,,,,fail,1,仓促收场,手滑了。,节奏乱了，但结局没有改变。
```

## 3. 匹配优先级

每个字段（标题 / 台词 / 描述）单独挑，规则一样：

1. 类型完全一致 +10
2. 指定了受害者 +8
3. 指定了地形 +4
4. 指定了杀手 +2
5. `kind=any` 不加类型分，只作为兜底

分数最高的一组里按 `weight` 随机。所以可以这样组合：

- 地形条目只写 `description` → 描述用地形文本
- 杀手条目只写 `title` / `line` → 标题台词用杀手文本
- 再加一条「某受害者 + 某地形」的条目 → 该角色在该地形会优先说专属文本

## 4. 日常操作

改完 CSV 后，在仓库根目录执行：

```powershell
node scripts/execution-texts.mjs import   # CSV → JSON
node scripts/execution-texts.mjs verify   # 检查两边是否同步
```

`npm run check` 会自动跑 `verify`；如果只改了 CSV 忘记 import，检查会直接报错。

其他命令：

```powershell
node scripts/execution-texts.mjs validate          # 只校验 CSV
node scripts/execution-texts.mjs export out.csv    # 把当前 JSON 导出成 CSV 模板
```

CSV 请保存为 **UTF-8**（Excel 选「CSV UTF-8」），否则中文会乱码。

## 6. QTE 是通用系统

QTE 不再绑在处决上。任何玩法都可以这样接入：

```ts
import { startQte } from './ui/qte';

startQte({
  label: '撬锁',
  length: 5,
  durationMs: 5000,
  anchor: () => document.querySelector('.lock-marker'),
  onComplete: ({ success, elapsedMs }) => {
    if (success) unlockDoor();
    else triggerAlarm();
  },
});
```

可用 API（`src/ui/qte.ts`）：

| 函数 | 作用 |
| --- | --- |
| `startQte(options)` | 开始一段 QTE；已有 QTE 时返回 `false` |
| `handleQteInput(key)` | 输入一位数字；返回是否被 QTE 消费 |
| `cancelQte()` | 取消当前 QTE，不触发回调 |
| `isQteActive()` | 是否有 QTE 进行中 |
| `syncQtePanel()` | 界面重绘 / 缩放后重新定位面板 |

接入方只需要在 `onComplete` 里决定成功/失败后果；QTE 本身不读写对局状态。

当前处决的接入示例在 `src/main.ts` 的 `startExecutionQte()`：血点达到 2000 后出现「QTE 处决」按钮，成功额外 +300 血点，失败仍完成处决。
