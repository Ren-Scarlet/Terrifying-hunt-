## 一、一局的骨架

### 1.1 模式、回合上限与胜负

| 模式 | 回合上限 | 说明 |
| --- | --- | --- |
| 契约模式 | **20 回合**（`CONTRACT_TURNS = 20`） | 开局随机发放一张契约；完成全部「主目标」后可以主动结算，也可以继续做额外挑战。 |
| 自由猎杀 | **99 回合** | 不发放强制契约，至少击杀 1 人后才能主动结束。 |

- **主目标完成**：`checkImmediateWin()` 检查所有非可选任务；全部达标后标记 `missionPrimaryCompleted`，之后随时可以结算（`finishContract`）。
- **到达回合上限**：回合结束时若 `turn >= mission.turns`，主目标已完成就判胜，否则按 `timeout`（超时）结算。
- **失败条件**：任务指定目标（名单目标）逃离 → 立即失败；所有人类都逃走且主目标未完成 → 失败；主动放弃 → 失败。
- 若所有人类逃走但主目标已经完成，结算为胜利（`escapePhase` 中的判断），不是失败。

### 1.2 一回合的流程

一个回合分成「玩家行动」和「世界结算」两部分：

| 阶段 | 发生什么 | 代码位置 |
| --- | --- | --- |
| 玩家行动 | 花费行动点（AP）移动、挥刀、出牌、搜索、使用能力或互动。 | `src/game/engine.ts` 中的各个动作函数 |
| 每次行动之后 | `afterPlayerAction()`：幸存者立刻反应、状态计时减 1、脚印/痕迹老化、恶魔附身扣尾随值。**不是等到回合结束才动。** | `afterPlayerAction()` |
| 结束回合 | `endTurn()` 依次结算：护士疲惫、鬼面夜幕、图腾余响、`npcTurn()`（流血/倒地倒计时/救援/移动）、`callPhase()`（报警）、`escapePhase()`（逃生）、`policePhase()`（警察）、`witnessPhase()`、警报自然衰减、冷却/锁门倒计时。 | `endTurn()` |
| 进入下一回合 | 天亮压力（每 5 回合一次）、行动点恢复、`attackReady` 恢复、抽 1 张牌、手牌上限检查。 | `endTurn()` 尾部 |

要点：

- **刀不是想砍就连砍**：挥刀后 `attackReady = false`，必须先移动、出一张牌、用能力或「擦刀」（1 AP）把它收回来，才能再砍。
- **每个动作都会让世界动一下**：所以「砍一刀 → 他跑两间屋 → 你跟上去」是正常节奏，不是额外惩罚。
- 手牌上限 6 张；超过上限时必须先弃牌。开局抽 5 张，每回合开始补 1 张，也可以花 1 AP 主动抽 1 张。

### 1.3 行动点（AP）

| 项目 | 数值 | 说明 |
| --- | --- | --- |
| 每回合基础 AP | **4**（`BASE_AP`） | 开局 AP = `max(1, 4 + 配件 ap 修正)`；`maxEnergy` 在开局固定。 |
| 移动 1 间房 | 1 AP | 迈尔斯处于「尾随者模式」时移动为 2 AP；`freeMove` 效果下为 0 AP。 |
| 普通挥刀 | 1 AP | `ATTACK_COST`。 |
| 出一张牌 | 卡面费用 | 费用 0～6；`discount` 可临时减费。 |
| 搜索当前房间 | 1 AP | `SEARCH_COST`。 |
| 查看相邻房间 | 1 AP | `LOOK_COST`。 |
| 主动抽 1 张牌 | 1 AP | `DRAW_CARD_COST`。 |
| 擦刀 | 1 AP | 把 `attackReady` 收回，可以接着砍。 |
| 砸电话 / 破坏木板 / 破门 / 砸电闸 | 1 AP | 破坏木板与破门会惊动屋里的人。 |
| 抱起 / 放下倒地者 | 各 1 AP | 搬运距离 ≥ 3 后每次移动要做 D6 检定，失败会被挣脱。 |
| 普通处决 / 地点处决 / 分数处决 | 各 1 AP | 见第四节。 |
| 杀手能力 | 通常 1 AP | 具体看 `src/game/data/killers.ts` 的能力定义。 |

回合开始时的 AP 公式（`endTurn`）：

```text
AP = max(1, maxEnergy + bonusEnergyNextTurn + frenzyBonus - stunTurns)
frenzyBonus = (杀戮值 >= 50) ? 2 : 0
```

- 没用完的 AP **不会保留**到下一回合。
- 幸存者反击或某些能力会造成 `stun`，直接减少下回合 AP。
- 卡牌/能力给的 `energy`/`steps` 是加到当前 AP 池，上限 99。
- 站在图腾房间结束回合，下回合额外 +1 AP（`bonusEnergyNextTurn`）。

### 1.4 警报、逃生点与最终危机

警报（`alarm`，0～100）是唯一的全局失败压力条；开局为 **12 + 配件 `startAlarm` 修正**。旧卡牌里的 `wanted`（暴露度 0～10）只是它的镜像：`wanted = ceil(alarm / 10)`，`wanted` 指令按 ×10 折算成警报。

| 阈值 | 发生什么 |
| --- | --- |
| **60** | 第一次达到 60 时，随机选取地图上最远的一对房间（排除大厅入口与车库出口）作为两个**逃生点**，并写进日志。高度警觉的幸存者会开始找出口。 |
| **100** | 进入**最终危机**（`emergencyActive = true`）：所有存活人类警觉≥85、意图改为逃跑；实体杀手会额外刷 3 名增援警察，灵异杀手则移除场上的警察；此后警报不再自然衰减。 |

警报的常见增减（只列代码里能确认的）：

| 事件 | 变化 |
| --- | --- |
| 攻击但没倒地 | +3 |
| 把目标打倒地 | +4 |
| 击杀后附近有人被惊动 | +6 |
| 普通处决（被目击 / 没被目击） | +8 / +1 |
| 地点处决 | 先 +6 或 +2，再固定 +8 |
| 分数处决 | +8 / +1 |
| 攻击警察 | 先 `addWanted(6)` = +60，再 +12（日志里的「+72」） |
| 有幸存者成功逃离 | +10 |
| 回合结束自然衰减 | -6；若本回合没有任何「热度」再 -4 |
| 跨过天亮阶段 | +4 |
| 最后 5 回合 | 每回合额外 +2 |

逃生点结算（`escapePhase`）：人站在逃生点且处于逃跑/高警觉状态时，第一次结算把 `escapeProgress` 置为 1（日志「下回合就会逃出去」），下一次结算才真正离场并 +10 警报。出口被封锁（`exitBlockedTurns`）或房门被锁时不会离开。名单目标逃走会立刻失败；其他人逃走只扣分，逃光且主目标未完成才失败。

### 1.5 天亮时钟

- 天亮阶段 0～3，每 **5 回合**推进一档（`floor((turn - 1) / 5)`，上限 3）。
- 每次跨阶段：警报 +4，所有存活人类警觉 +5。
- 最后 5 回合：每回合额外警报 +2。
- 这是「外部时钟」，不直接扣 AP；它的作用是让局面越来越紧。

### 1.6 评分与战利品（和调数值有关的部分）

- **分数处决门槛**：实时评分达到 **200**（`SCORE_EXECUTION_THRESHOLD`）后，倒地者头顶才会出现分数处决按钮。
- 评分主要项：击杀 14/人、处决 10/次、处决方式多样性 10/种（超过 1 种的部分）、恐惧崩溃击杀 8、连杀 12、无目击击杀 3（上限 10）、全程无人报警 +25、低警报 +15、策略行为最多 +60、卡牌多样性最多 +15、剩余回合 5/回合（仅胜利结算）、逃跑每人 -15、警报 ≥60 后每 5 点 -1、抓捕/超时/失败另有扣分。这些数值在 `engine.ts` 的 `SCORE_RULES` 里。
- 战利品：击杀 +20；普通处决额外 +15（地点处决与分数处决不吃这 15）。胜利或自由猎杀全额带走，失败只保留 30%（再乘配件 `lootPct` 修正）。

## 二、生命、伤害与状态

### 2.1 4 → 2 → 0：生命与倒地

```text
生命 4、3        健康（healthy）
生命 2、1        受伤 / 重伤（injured）  ← 阈值 SURVIVOR_INJURED_HP = 2
生命 0           倒地（downed）
```

- `SURVIVOR_MAX_HP = 4`，`SURVIVOR_INJURED_HP = 2`。
- **倒地不是死亡**。倒地者不能行动，但可以被处决，也可能被同伴救起；**只有处决、对倒地者继续造成伤害、或倒地倒计时走完才会死**。
- 一次伤害可以把人从满血直接打到 0（例如 4 点伤害），但**不会越过「倒地」直接杀死站立者**：`damagePerson()` 对 `hp > 0` 的人最多把 hp 压到 0 并标记倒地。
- 反过来，**对已经倒地的人再造成任何伤害 = 补刀**：`damagePerson()` 会直接 `killPerson()`，并计一次处决（`executions + 1`）。

倒地后的死亡倒计时（`BLEEDOUT_TURNS = 4`）：

- 每次回合结束的 `npcTurn()` 里，倒地者的 `downedTurns + 1`；累加到 **4** 时死亡（警报 +10）。
- 被杀手抱着搬运时**倒计时不会暂停**，照样每回合 +1，抱满 4 回合会死在怀里。
- 因为倒地当回合结束时就会先 +1，所以通常表现为「倒地后还能撑 4 次回合结束」，UI 显示「还有 4 - n 回合」。
- 若是在回合结束的流血结算里被流倒，倒计时从下一次回合结束才开始数，实际会多出约一回合。

### 2.2 伤害结算的细节（`damagePerson`）

`damagePerson(state, person, amount)` 的实际顺序：

1. 目标已不在场上 → 直接返回。
2. `dmg = max(0, amount + state.bonusDamage)`，然后**立刻清空** `bonusDamage`（「下次攻击 +X」只吃一次）。
3. `dmg <= 0` → 不产生伤害。
4. 目标有 `danger`（危险）状态且还站着 → **立即倒地**（消耗 `danger`），不走普通扣血。
5. 清空杀戮值（`frenzy = 0`）；按 `fearOnHit` 修正增加恐惧；恐惧达到 100 时，本次伤害至少等于目标当前生命（也就是会被打倒地）。
6. 目标原本已倒地（`before <= 0`）→ 计一次处决并击杀。
7. 否则扣血：`hp = max(0, hp - dmg)`。
8. 扣到 0 → 倒地，`downedTurns = 0`，警报 +4，惊动目击者。
9. 没倒地 → 警觉拉满、开始逃跑，并**当场连跑 2 间屋**（`PANIC_HOPS_ON_HIT = 2`），警报 +3。

> 结论：普通一刀 1 点，从满血打倒地需要 4 刀；第 2 刀后进入「受伤」。所谓「一刀倒地」一定是叠加了别的机制，见 2.6。

### 2.3 治疗与救援

| 方式 | 代码 | 效果 |
| --- | --- | --- |
| 治疗（`heal` 指令） | `healPerson()` | 只能治 `hp > 0` 的人；回复 `amount` 点，上限 4；目标有 `incurable`（不治）时上限为 2。`amount >= 2` 且目标有 `deepWound` 时会清掉深度伤口。 |
| 救援（`rescue` 指令） | `rescuePerson()` | 只能对倒地者使用；倒地 → 受伤（hp = 2），清空倒地倒计时，警报 +2。 |
| 幸存者 AI | `tryRescue()` | 同屋且杀手不在场时，幸存者可能把倒地同伴拉起来（倒地 → 2 HP），或给受伤同伴包扎 1 点；不同性格的成功意愿不同。 |

> 当前源码内置的 25 张卡牌里**没有** `heal` / `rescue` 指令；这两个效果主要给幸存者 AI 和以后的自定义卡使用。在平衡面板「添加效果」里可以选到它们。

### 2.4 流血（bleed）

流血不是「每层造成多少伤害」，而是**层数 = 还要结算几次**：

- 每个回合结束的 `npcTurn()` 里，若 `bleed > 0`：先损失 **1 点生命**（固定 1，不吃层数、不吃 `bonusDamage`），然后 `bleed -= 1`。
- 因此「流血 2」= 接下来 **2 次回合结束**各掉 1 点，共 2 点，不是每回合掉 2 点。
- 流血伤害走 `damagePerson()`，所以会触发恐惧、逃跑（再跑 2 间屋）、倒地与处决计数；如果这一下把人打倒地，`bleed -= 1` 会被跳过，层数留在身上（但倒地期间不再结算流血）。
- 多个流血来源只增加层数（`bleed += amount`），延长时间，不提高每回合伤害。
- `deepWound`（深度伤口）状态存在时，每个 NPC 回合都会把 `bleed` 至少拉到 1，等于「伤口一直流血，直到状态消失」。状态本身按**玩家行动次数**递减（见 2.5）。

**留血迹**：不是流血专属。幸存者移动时，只要 `hp <= 2` **或** `bleed > 0`，就会在地上留下 `blood: true` 的脚印；脚印保留 3 次玩家行动（`TRAIL_ACTION_WINDOW = 3`）。猎鹿者等效果会高亮最新脚印。

### 2.5 状态一览

状态存在 `person.statusEffects` 里，每种状态的值是「剩余次数」。施加时统一写成 `turns + 1`，然后**每次玩家行动后减 1**，所以玩家实际看到的是 `turns` 次后续行动。

| 状态 | 中文 | 实际效果（代码） |
| --- | --- | --- |
| `blind` | 障目 | 该幸存者无法感知杀手（`cannotSenseKiller`）。 |
| `undetectable` | 无法侦测 | 同上，用于让幸存者看不见你。 |
| `danger` | 危险 | 下一次受到伤害时**立即倒地**，并消耗此状态。 |
| `deepWound` | 深度伤口 | 每个 NPC 回合强制 `bleed >= 1`；治疗 `amount >= 2` 可清除。 |
| `oblivious` | 浑然不觉 | 同上，使幸存者无法感知杀手。 |
| `incurable` | 不治 | 治疗上限降为 2。 |
| `cursed` | 被诅咒 | 每个 NPC 回合恐惧 +8、警觉 +5；场上图腾全被拆掉后自动解除。 |

注意：

- `deepWound` 本身**不直接扣血**，它只是保证流血不断。
- 状态的持续时间按「玩家行动」而不是「回合」走；一张 0 费卡也会让状态减 1。
- 若用面板把 `statusTurns` 设为 0，`attack` 指令**完全不会施加状态**（见第三节）。

### 2.6 攻击伤害公式与「一刀倒地」

普通挥刀 `attack()` 的伤害（`src/game/engine.ts:3421` 附近）：

```text
heavy = state.possessed                       // 恶魔附身
noedActive = hexNoedActive && alarm >= 100 && totems.length > 0   // 难逃一死

baseDamage =
    noedActive || (heavy && killer === '迈克尔·迈尔斯')  ? 4
    : min(4, 1 + modifierValue(state, 'attackDamage'))   // 基础 1 点

comboDamage = (目标 blockedTurns > 0 && baseDamage < 4) ? 1 : 0

若 noedActive：造成 4 点（警察也是 4 点）
否则：造成 baseDamage + comboDamage 点
```

其中：

- **基础挥刀 = 1 点**（不是 2 点；`cards.ts` 顶部注释里「默认 2 点」是过时说法）。
- `attackDamage` 来自配件统一修正层（`modifiers.ts`），上限被 `min(4, …)` 夹住；目前源码里的配件没有任何一件带 `attackDamage`，所以默认局内就是 1。
- **控制连携**：目标处于 `blockedTurns > 0`（被定身）时 +1 伤害。这是「先控再砍」的核心收益。
- **追踪连携**：目标 `trackedTurns > 0` 时不加伤害，只额外 +10 猎杀评分。
- `noedActive`（难逃一死）与迈尔斯恶魔附身都直接给 4 点，**不再叠加** `attackDamage`/控制连携的额外伤害（`comboDamage` 只在 `baseDamage < 4` 时才有）。
- 配件加伤可以被「恐惧 100」等机制进一步放大：`damagePerson` 在恐惧满值时会把本次伤害抬到目标当前生命。

**「一刀倒地」的真实条件**（按代码逐一核对）：

| 情况 | 是否一刀倒地 | 说明 |
| --- | --- | --- |
| 难逃一死生效（`hex_noed` 已打出 + 警报 100 + 至少 1 座图腾） | 是 | 直接 4 点伤害，满血也倒地；图腾被拆光、警报未满、或没打出 `hex_noed` 都不生效。 |
| 迈克尔·迈尔斯恶魔附身 | 是 | 尾随值满 100 后开能力进入附身，挥刀 4 点；每次行动消耗 20 点尾随值（配件可减少），归零退出。 |
| 目标只剩 1 点生命（已受伤的残血） | 是 | 1 点伤害正好归零。 |
| 目标受伤（2 点）+ 控制连携 +1 | 是 | 例如先用「牢牢紧握」定身，再砍：2 点伤害归零。 |
| 目标受伤（2 点）+ 配件 `attackDamage +1` | 是 | 目前没有这样的配件，改数据/自定义后成立。 |
| 目标有 `danger` 状态 | 是 | 任何伤害都直接倒地。 |
| 目标恐惧 100 | 是 | 本次伤害被抬到「当前生命」，直接倒地。 |
| **目标只是受伤（2 点），普通一刀 1 点** | **否** | 会剩 1 点生命；这是最容易误解的一条。 |

## 三、重点：辣手屠夫

### 3.1 卡牌数据

| 字段 | 值 |
| --- | --- |
| id | `sloppy_butcher` |
| 名称 | 辣手屠夫 |
| 类型 | `skill`（技能） |
| 费用 | **1** |
| 卡池 / 解锁 | `initial`（通用初始池），默认已解锁 |
| 描述 | 立即对当前房间一名站立幸存者发动一次攻击；命中后附带流血 2 回合，移动时留下血迹。 |
| ops | `[{ op: 'attack', who: 'victim', bleedTurns: 2, status: 'deepWound', statusTurns: 0 }]` |

### 3.2 实际结算顺序

1. **出牌检查**：`playCard()` 找到 ops 里的 `attack` 指令，用 `who: 'victim'` 在当前房间选一名**站立**的非警员目标（优先标记目标 > 目标 > 平民）。
2. **没有目标不消耗**：选不到人时只写日志，不扣 AP、不弃牌。
3. **攻击前检查**：`attackBlockReason()` 检查「刀已收回（`attackReady`）且 AP ≥ 卡牌费用」；紧接上一刀是打不出的。
4. **消耗卡牌与 AP**：卡牌进弃牌堆，AP 扣 1（卡牌费用被当作这次攻击的 `costOverride`，不会另收一次攻击费）。
5. **执行真正的挥刀 `attack()`**：
   - 基础伤害 1 点（可受配件/控制连携影响）；
   - 若目标掉血（`hp < 挥刀前` 且仍在场），把 `bleed` 设为至少 **2**（`max(bleed, 2)`）；
   - `statusTurns` 为 0 → **不施加 `deepWound`**（见 3.3）；
   - 挥刀后 `attackReady = false`，必须再做一次动作才能再砍。
6. **目标受击反应**：如果这一刀没倒地，目标警觉拉满并当场连跑 2 间屋，同时开始流血。
7. **回合结束流血结算**：每个回合结束的 `npcTurn()` 掉 1 点、`bleed` 减 1；流血造成的伤害同样会让目标逃跑。

### 3.3 为什么 `status: 'deepWound'` 没生效

`playCard()` 里这一句决定了命中后状态的去留：

```ts
return attack(state, victim.id, {
  costOverride: cost,
  bleedTurns: attackOp.bleedTurns,
  hitStatus: attackOp.statusTurns > 0 ? attackOp.status : undefined,
  hitStatusTurns: attackOp.statusTurns,
});
```

- `statusTurns = 0` → `hitStatus = undefined`，`attack()` 里施加状态的代码要求 `(hitStatusTurns ?? 0) > 0`，所以**深度伤口永远不会挂上**。
- 因此「辣手屠夫」现在的实际效果是：**一次普通挥刀（1 点）+ 流血 2 次结算 + 移动留血迹**；`status`/`statusTurns` 是「预留但未启用」的字段。
- 如果确实想让它附带深度伤口，在平衡面板把 `statusTurns` 改成 1（或更多）即可；改成 1 后，状态会被写成 `1 + 1 = 2` 次行动，然后按玩家行动递减，期间每个 NPC 回合强制 `bleed >= 1`，会显著加强这张牌。

### 3.4 一刀挥下去，完整时间线

以满血 4 点、没有其他状态的目标为例（假设玩家不再补刀）：

| 时间点 | 生命 | 流血层数 | 发生了什么 |
| --- | --- | --- | --- |
| 出牌瞬间 | 4 → 3 | 2 | 挥刀 1 点，挂上流血 2；目标逃跑 2 间屋 |
| 本回合结束 | 3 → 2 | 1 | 流血掉 1，进入「受伤」，再逃跑；日志提示受伤 |
| 下回合结束 | 2 → 1 | 0 | 流血掉 1，仍站着，流血结束 |
| 再下一回合 | 1 | 0 | 不再掉血；需要补刀或其它伤害 |

所以：**满血目标被辣手屠夫砍一刀不会自己倒地**，2 次流血结算总共只造成 3 点伤害（1 + 1 + 1），最后剩 1 点。如果目标受击前已经受伤（2 点），这一刀 + 流血会更快把他放倒。

### 3.5 那为什么有时「一刀就倒」？

对辣手屠夫来说，常见的叠加方式：

- **目标已经只剩 1 点生命**：这一刀的 1 点直接归零。
- **目标处于定身（`blockedTurns > 0`）**：控制连携 +1，总共 2 点；受伤目标（2 点）会当场倒地。
- **难逃一死已生效**：无论目标多少血，攻击直接 4 点倒地（但 `hex_noed` 要提前打出，且警报必须满 100、图腾至少剩 1 座）。
- **迈尔斯恶魔附身**：挥刀 4 点，满血也倒。
- **目标有 `danger` 状态**：任何伤害都直接倒地。
- **目标恐惧 100**：伤害被抬到当前生命，直接倒地。

> 注意：目标「只是受伤」并不足以被普通一刀放倒——普通刀只有 1 点。必须再叠加控制连携、配件加伤、危险状态、恐惧满值、难逃一死或恶魔附身之一。

### 3.6 调这张牌时要注意

- **`bleedTurns`**：改成 3 就是 3 次回合结束各掉 1 点；不是每回合掉 3 点。对满血目标，`bleedTurns >= 3` 才能靠流血单独放倒（1 + 3 = 4）。
- **`statusTurns`**：0 = 不施加状态；改成 ≥1 才会挂 `deepWound`，而 `deepWound` 会让流血一直续到状态结束，实际强度比数字看起来高。
- **`who`**：即使改成 `allHere`、`injuredAny` 等群体选择器，`playCard()` 也只对 `selectPeople(...)[0]` 选中的第一个人发动攻击，其余目标会被忽略；要群体攻击必须改引擎。
- 卡牌自带的 `attack` 会吃掉本次挥刀机会，并使 `attackReady = false`；不要指望它能在同一回合接普通挥刀。

## 四、三种处决

倒地后**立刻**可以处决（`canExecuteNow()` 只检查 `hp <= 0`；`DOWNED_LOCK_TURNS = 0`）。三种处决互相独立：

| | 普通处决 | 地点处决 | 分数处决 |
| --- | --- | --- | --- |
| 触发入口 | 倒地者身上的「处决」按钮 | 抱起倒地者 → 搬到指定房间 → 选择该房间的处决方式 | 倒地者头顶的「分数处决 · QTE」按钮 |
| 前置条件 | 目标在当前房间、已倒地 | 目标已抱起、当前房间是处决地点 | 当前评分 ≥ 200、目标在当前房间、已倒地、未被抱起 |
| AP | 1 | 抱起 1 + 搬运若干 + 处决 1（放下另 1） | 1 |
| 立即处决？ | 是 | 是（到地点后） | 是（QTE 成败都完成处决） |
| 处决本身警报 | 被目击 +8 / 没被目击 +1 | 先 +6/+2，再固定 +8 | +8 / +1 |
| 额外收益 | 战利品 +15 | 额外 +35 分，并记录处决方式多样性 | 额外 +25 分；完美 QTE 再 +25 分 |
| 评分 | 处决 +1 次（10 分/次） | 处决 +1 次；方式多样性 10 分/种 | 处决 +1 次；`scoreExecutions +1` |
| 主要风险 | 低 | 搬运距离 ≥3 后每次移动要 D6，失败会被挣脱（目标回到 2 HP 逃跑） | QTE 失败只少加分，处决仍然完成 |

补充：

- **普通处决**走 `executePerson()`：可以处决刚倒地的人，不需要等；处决后 `attackReady` 会被重置为 `true`。普通处决不额外加分，只有「处决 +1 次」（10 分/次）与 +15 战利品。
- **地点处决**的 6 个地点（`src/game/executions.ts`）：厨房（冰柜封存 / 微波灼刑）、车库（车库碾压）、工具间（工具间终结）、浴室（浴缸溺杀）、洗衣房（烘干机封喉）。必须把目标抱到对应房间；抱起期间目标仍按 `BLEEDOUT_TURNS` 倒计时，可能死在路上。
- **分数处决**的 QTE：4 位随机数字、4.2 秒内按顺序输入；错一位或超时算失败。QTE 结果**不影响处决是否完成**，只影响额外 +25 分与场内幸存者的恐惧/警觉变化（完美：全场未躲藏的存活者恐惧 +22、警觉 +8；失误：只影响当前/相邻房间，恐惧 +12、警觉 +5）。注意引擎在处决时已经先给了 +25 分，完美 QTE 是**额外再加 25**，合计 +50。
- 处决/击杀还会触发 `killPerson()` 的后续：附近的人恐惧/警觉上升、警报 +6；上表只列「处决动作本身」的警报。

## 五、卡牌与构筑

当前源码内置 **25 张**卡牌：

| 卡池 | 数量 | 获得方式 |
| --- | --- | --- |
| 通用初始池 `initial` | 12 | 默认解锁，所有杀手共用。 |
| 杀手专属池 `killer` | 9 | 默认解锁，但只有对应杀手能带进牌组（迈尔斯 / 设陷者 / 护士各 3 张）。 |
| 商店池 `shop` | 4 | 初始未解锁；在商店花血点购买，价格 = `20 + 费用 × 15`（当前为 35 或 50 血点）。 |

完整表格（id、名称、类型、费用、解锁、描述、ops）见 [卡牌一览.md](卡牌一览.md)。那张表由脚本从源码生成，改完 `src/game/data/cards.ts` 后重新运行：

```bash
node scripts/export_cards.mjs
```

脚本用项目已有的 `esbuild`（devDependency）在内存里打包并 import，不联网、不写临时文件；首次使用前需要 `npm install`。它只读取源码内置卡牌，不会把平衡面板里的本地覆盖或自定义卡写进表里。

构筑规则（`src/game/save.ts`）：

- 牌组 10～15 张，同一张卡最多 3 张；不满足时回退到起始牌组。
- 开局抽 5 张；每回合开始补 1 张；手牌上限 6。
- 商店卡即使没买也会出现在牌组编辑器里，但显示为未解锁，不能选中。
- 目前 `UNLOCK_REWARDS` 是空表：**打完契约不会解锁新卡**，任务奖励卡机制只是预留。

出牌规则要点：

- `precheck` 不满足时只提示、不扣 AP、不弃牌。
- `noAction: true` 的卡（例如「恶灵低语」）打出后不推进幸存者行动、不减状态计时；不是「不花 AP」。
- 卡牌效果由 `ops` 逐条执行；描述与 ops 冲突时以 ops/引擎为准。
- 带 `attack` 指令的卡比较特殊：`playCard()` 找到 ops 里的**第一条** `attack` 后就直接走攻击分支并 `return`；这条 `attack` 之前和之后的其它 ops 都不会执行。它会把卡牌费用当作这次攻击的费用，所以「攻击 + 其它效果」的复合写法目前不会按顺序全部执行。
- 少数卡在 `playCard()`/引擎里有硬编码分支（例如 `myers_eclipse_light`、`myers_last_best`、`hell`、`unbreakable`），只改 ops 不会改变这些分支。

## 六、不改代码也能调数值

### 6.1 平衡调整面板（`?admin=1`）

**入口**：当前构建没有主菜单按钮，唯一入口是网址后加查询参数：

```text
https://<游戏地址>/?admin=1
本地开发：http://127.0.0.1:5173/?admin=1
```

加载后直接打开「平衡调整」面板；关闭后要重新带 `?admin=1` 刷新才能再进。

面板左上角的状态：

- **「使用原始数值」**：没有本地覆盖。
- **「正在使用本地改动」**：`hasTuning()` 为真，至少有一项被改过。

**三个标签页能改什么**：

| 标签页 | 可改字段 | 范围 / 说明 |
| --- | --- | --- |
| 卡牌 | 费用 | 0～6 的整数。 |
| | 名称 | 最多 60 字。 |
| | 类型 | 攻击 / 技能 / 战术 / 布置。 |
| | 描述 | 最多 500 字（只影响文案，不影响结算）。 |
| | 风味文字 | 最多 160 字。 |
| | `noAction` | 勾选后打出不推进幸存者行动。 |
| | 每条 op 的字段 | 目标、数值、回合、状态、目的地、开关等，按 `effectCatalog` 的字段类型显示为数字框或下拉框。 |
| | 添加 / 删除 / 上下移动 op | 单卡最多 30 条 op；新 op 用默认值生成。 |
| | 出牌条件 `precheck` | 无 / 当前房间有可攻击目标 / 有倒地目标 / 有受伤目标 / 有目标在别处 / 视野内有存活者 / 附近有幸存者 / 正抱着人 / 有可破坏物。 |
| | 新建 / 复制 / 删除卡牌 | 新卡 id 自动生成 `custom_card_N`；新卡默认加入通用池。 |
| 杀手能力 | 冷却 `cooldown` | 1～8 回合。 |
| | 每条 op 的数值 | 与卡牌相同。 |
| 配件 | 说明文字 | 最多 500 字。 |
| | 修正键数值 | 只能改这件配件**已经定义**的键（例如 `trapDamage`、`blinkRange`、`ap`），范围 -1000～1000；不能凭空加键。`attackDamage` 虽然在类型和引擎里存在，但当前没有任何配件定义它，所以面板里也调不到。 |

**字段速查**（ops 里常见字段）：

| 字段 | 含义 |
| --- | --- |
| `who` | 目标选择器：当前目标、房间内血最少、全场最警觉、房间内所有目标、全场所有人、倒地者、受伤者、血祭品等（完整中文选项见面板下拉框）。 |
| `amount` | 数值（伤害、恐惧、警报、行动点、抽牌数等，随 op 而定）。 |
| `bleedTurns` | 命中后流血结算次数；每次结算只掉 1 点。 |
| `status` / `statusTurns` | 命中后施加的状态与持续次数；`statusTurns = 0` 时不施加。 |
| `turns` | 持续回合/次数（定身、追踪、锁门、封报警等）。 |
| `to` / `room` | 目的地/房间（当前、相邻、最远，或具体房间）。 |
| `key` | 开关或设施键：`phoneCut`、`wiretap`、`hexNoed`、`phone`、`exit` 等。下拉框只列出 `effectCatalog` 收录的键；`stealthNext` 等未收录的键虽然引擎支持，但只能通过导入 JSON 或改源码使用。 |
| `value` | 开关的值；数字或 true/false。 |
| `maxHp` | `damage` 的过滤条件：只打生命上限 ≤ 该值的人。 |
| `count` / `distance` | 噪声吸引人数 / 追击距离。 |

> 已知面板小坑：「静止隐身」的 `flag` 是 `stealthNext`，但 `effectCatalog` 的开关下拉没有收录这个键，面板会把该下拉显示成第一个选项（`phoneCut`）。**不要在这个下拉里重新选值**，否则会把卡改成「剪电话」；要改它请用导入 JSON 或改源码。

**改动保存到哪里**：

- 没有「保存」按钮；每次输入/下拉变化都会立即写回运行时数据，并自动写入浏览器 **localStorage 的 `night-hunt-tuning-v2`**。
- 关闭页面、刷新、重启浏览器后仍然生效；换浏览器/换设备不会自动带过去。
- 数据是「覆盖层」：只记录改过的卡/能力/配件，没改的继续用 `src/game/data` 的原值。

**导出 / 导入 / 重置**：

- **导出数据**：展开一个只读文本框，内容是完整的调参 JSON（`cards` / `powers` / `addons` / `customCards` / `deletedCards`）；旁边有「复制」。
- **导入 JSON 备份**：把之前导出的 JSON 粘贴到文本框，点「校验并导入」。
  - 会校验卡牌/能力 ID、ops 结构与数值范围；不合法时**不会覆盖**当前配置。
  - 合法的云端配置或备份会**整体替换**当前本地调参，而不是合并。
- **恢复默认**：立即清空覆盖层（`resetTuning()`），把卡牌费用/描述/ops、能力冷却/ops、配件说明/数值恢复成 `src/game/data` 的原值；无需确认，不可撤销。
- 面板里的「正在使用本地改动」只反映本地覆盖；云端配置导入后也算本地覆盖。

**云端同步（可选）**：

- 需要 GitHub 管理员密钥：Fine-grained Personal Access Token，账号必须是 `Ren-Scarlet`，仓库限定 `Ren-Scarlet/Terrifying-hunt-`，权限 `Contents: Read and write`。
- 密钥只存在当前页面内存，刷新后要重新验证；`initCloudAuth()` 目前是空实现。
- **上传当前配置**：把当前 `exportTuning()` 写到仓库 `main` 分支的 `data/game-config.json`。
- **读取云端配置**：拉取同一路径，校验后导入本地。
- 所有玩家启动时都会尝试读取这份公开配置（`raw.githubusercontent.com`，不缓存）；读取失败只 `console.warn`，不影响本地游戏。
- **重要**：启动顺序是「先应用本地 localStorage 覆盖 → 再拉云端配置」。如果云端存在且合法，它会**整体替换**本地配置；因此本地改完想保留，先导出备份，或确认云端没有旧配置。
- 云端配置始终读 `main` 分支的 `data/game-config.json`，与页面来自哪个预览路径无关。

### 6.2 平衡面板改不了的东西

面板只覆盖「卡牌费用 + 卡牌 ops 数值 + 能力冷却/ops + 配件已定义修正值」。以下属于引擎硬编码，必须改代码：

- 基础挥刀伤害 1、控制连携 +1、难逃一死的 4 点；
- 生命上限 4、受伤阈值 2、倒地倒计时 4；
- 流血每回合固定 1 点；
- 基础 AP 4、每回合补牌 1、手牌上限 6、契约 20 回合；
- 警报 60/100 的阈值与自然衰减；
- 评分规则、战利品比例、处决的 AP/警报/加分；
- 新 op 类型本身（只能在现有 op 里调数值）。

### 6.3 直接改源码数据（需要重新构建）

想改「默认值」而不是本地覆盖，改这些文件：

| 想改什么 | 文件 |
| --- | --- |
| 卡牌费用、名称、描述、ops | `src/game/data/cards.ts` |
| 杀手能力冷却与 ops | `src/game/data/killers.ts` |
| 配件修正值（`attackDamage`、`blinkRange` 等） | `src/game/data/accessories.ts` |
| 生命/AP 等核心常量 | `src/game/constants.ts` |
| 伤害公式、流血、倒地倒计时、处决、评分 | `src/game/engine.ts` |
| 配件修正层的基础值（飞斧、闪现、附身消耗等） | `src/game/modifiers.ts` |

关于 `src/game/tuning.ts`：

- 它是**运行时覆盖层 + 校验器 + localStorage 读写**，不是数值表。默认数值来自 `src/game/data/*.ts`，在模块加载时被克隆成 baseline。
- 一般调数值**不需要改 `tuning.ts`**；只有要改 localStorage 键名、校验范围、导入格式时才动它。
- 如果改了 `data/*.ts` 而本地还留着旧的 localStorage 覆盖，旧覆盖会继续生效；调完默认值后记得在面板点「恢复默认」，或清掉 `night-hunt-tuning-v2`。

构建步骤（在项目根目录）：

```bash
# 第一次
npm install

# 改完源码后：先类型检查（可选），再构建
npm run typecheck
npm run build

# 本地预览构建产物（默认 http://127.0.0.1:4173）
npm run preview
```

- `npm run build` = `tsc && vite build && node scripts/build-sw.mjs`：类型错误会直接中断构建；构建完会在 `dist/` 里额外生成离线用的 `sw.js`。
- 不要把 `dist/` 当源码改；它是构建产物。改了 `src/` 后重新构建即可，`sw.js` 会自动更新缓存清单与版本号。
- 正式站由 GitHub Actions 在 `main` 分支 push 时构建并部署；本地 `dist/` 适合自测或自行上传到静态服务器。
- 只改 `docs/` 不会影响游戏构建；`scripts/export_cards.mjs` 也只是读取源码，不参与打包。

### 6.4 推荐的调参流程

1. 用 `?admin=1` 面板快速试数值（本地立即生效，不影响别人）。
2. 满意后点「导出数据」复制 JSON，作为备份。
3. 把 JSON 发给开发者，固化进 `src/game/data/*.ts`；或者由管理员「上传当前配置」到云端，让所有玩家生效。
4. 想确认当前线上到底用了什么：看面板状态与云端 `data/game-config.json`；本地改动优先应用，但会被启动时拉到的云端配置整体替换。

## 七、常见问题

### 7.1 能离线玩吗？

- **生产构建支持离线缓存**：`npm run build` 在 `vite build` 之后会运行 `scripts/build-sw.mjs`，扫描 `dist/` 并生成 `dist/sw.js`；`src/main.ts` 只在生产构建（`import.meta.env.PROD`）里注册这个 Service Worker，作用域是 `./`（支持部署在子路径）。
- 缓存策略：
  - 页面导航：**先走网络**；断网时回退到缓存的 `index.html`（单页应用外壳）。
  - 同源静态资源（JS/CSS/图片/音频）：**缓存优先**，没命中再请求网络并写入缓存。
  - 跨域请求（例如 GitHub 的云端配置）不经过这个缓存，始终走网络。
- 所以：**首次打开必须联网**（让页面和静态资源进入缓存）；之后断网/离线再打开，已缓存的页面和资源仍能玩。`vite dev` 开发模式没有 `sw.js`，也不会注册 SW，离线测试要用 `npm run build` + `npm run preview` 或线上版本。
- 发版后缓存版本号由 `dist/` 文件清单的哈希决定（内容不变不会重复下载）；新 SW 安装后会 `skipWaiting` + `clients.claim`，旧缓存自动清理。第一次带新版本打开时仍建议刷新一次确认拿到更新。
- 游戏启动时会请求 GitHub 上的云端配置（`raw.githubusercontent.com/.../data/game-config.json`）。断网时这个请求失败会被 `try/catch` 吞掉，只打印 `console.warn`，本地存档、本地调参与离线缓存照常可用。
- 云端同步（验证密钥、上传、读取）必须联网；GitHub Pages 在线版首次加载也必须联网。
- 存档与调参都在浏览器 localStorage：`night-hunt-dossier-save-v1`（存档）与 `night-hunt-tuning-v2`（平衡覆盖）。清理浏览器数据会一起清掉（Service Worker 缓存也会没）。

### 7.2 手机网页版和「手机预览版」有什么区别？

根据仓库的部署工作流（`.github/workflows/deploy.yml`）：

- **正式站根目录**和 **`/preview/`** 来自 `main` 分支的同一次构建，内容完全一样（工作流把 `production/dist` 复制了两份）。
- **`/mobile-preview/`** 固定来自手机重构分支 `feature/mobile-ui-standalone` 的构建，是独立的手机界面版本，不复用 `main` 的构建。
- 三者共用同一个 GitHub Pages 部署；push 到 `main` 时才会部署，PR 只构建检查、不部署。

就本工作副本的 `main` 代码而言：

- 手机布局只在**对局界面**启用，条件是 `(max-width: 920px) and (pointer: coarse)`，即「窄屏 + 粗指针（触摸）」；菜单/牌组编辑器不走这套手机壳。
- 手机布局是独立的三段式界面（顶部目标与状态、中间地图、底部能力/操作/手牌），地图自动缩放到窗口内；竖屏为主，横屏会压缩上下 HUD。
- 由于根目录、`/preview/`、`/mobile-preview/` 在同一个域名下，**localStorage 是共用的**（存档与平衡覆盖都会互相影响）；但不同分支构建的卡表/机制可能不同，旧存档里的卡 id 会按当前构建过滤，必要时回退到起始牌组。
- 手机预览分支的具体界面与功能以该分支代码为准；本工作副本只能确认部署来源，无法替它保证与 `main` 完全同步。

### 7.3 改了数值但游戏里没变化？

按顺序排查：

1. 本地是否有旧的 localStorage 覆盖盖住了你改的默认值？看面板是否显示「正在使用本地改动」，必要时「恢复默认」。
2. 云端是否有配置？启动时云端配置会整体替换本地配置。
3. 改的是 `src/game/data/*.ts` 却没重新 `npm run build`，或者浏览器还在用旧缓存（强制刷新 / 换端口）。
4. 改的是卡面描述（`desc`），但实际结算是 `ops`；只改描述不会改变效果。
5. 改的是 `attack` 卡的 `statusTurns`，但值仍为 0（不施加状态）。
6. 改的是「基础挥刀伤害」这类引擎常量，面板改不到，必须改 `engine.ts`。

### 7.4 为什么卡牌描述和实际效果对不上？

描述是手写文案，ops 才是结算依据。已知的不一致见附录 A；改卡时建议同时检查 `ops` 与引擎里的特判分支。

## 附录 A：文案与实现不一致处

以下是阅读代码时确认的「描述/日志」与「实际结算」不一致，**均未修改代码**，仅供作者决策：

1. **`src/game/data/cards.ts` 顶部注释说「默认挥刀造成 2 点伤害……一刀受伤、两刀倒地」**
   - 实际：普通挥刀基础 **1 点**（`engine.ts` 的 `attack()`：`1 + attackDamage`），满血 4 点需要 **4 刀**才倒地，第 2 刀才进入受伤。
2. **「辣手屠夫」的 `status: 'deepWound', statusTurns: 0` 不会生效**
   - `playCard()` 只有在 `statusTurns > 0` 时才把状态传给 `attack()`；0 等于「不施加」。卡面/ops 里保留了这个字段，但目前是死字段。
3. **「厄咒：猎杀戾气」的运行时日志说「下一次击杀人类时获得额外猎杀评分」**
   - 实际：`attack()` 在**第一次命中并造成掉血**时就给 +50 分（`hexHuntressUsed`），不需要击杀；卡面描述（命中时）是对的，日志文案是错的。
4. **伏击与鬼面「夜幕」的日志声称额外伤害/直接倒地，但没有对应伤害代码**
   - `attack()` 里 `ambushStrike` 只写「造成重创（2 点伤害）」的日志，没有加伤害；`nightfallKill` 只写「这一刀直接把他放倒」并清状态，同样没有加伤害。按当前代码，它们不会真的改变这一刀的伤害。
5. **「牢牢紧握」描述是「下一次行动无法逃离当前房间」，实现是 `block`**
   - `block` 会让目标在 `blockedTurns` 期间**整个行动被跳过**（`npcTurn` 里直接 `continue`），比「无法逃离」更强：不能移动、不能报警、不能救援。
6. **`effects/runtime.ts` 的 `execute` 失败日志说「刚倒下的人要等两回合」**
   - 实际 `canExecuteNow()` 只判断 `hp <= 0`，倒地后**立即**可以处决；`DOWNED_LOCK_TURNS = 0`。日志是旧规则残留。
7. **`cards.ts` 的 `UNLOCK_REWARDS` 注释说「目前 18 张卡全部在 STARTER_CARDS 里默认解锁」**
   - 实际默认解锁 21 张（12 张通用 + 9 张杀手专属）；`UNLOCK_REWARDS` 为空，打契约不会解锁卡。
8. **`README.md` 说「所有幸存者成功逃离会导致杀手失败」**
   - 实际 `escapePhase()` 在最后一人逃走时，如果主目标已完成，会结算为**胜利**；只有主目标未完成才失败。
9. **卡牌 `insidious` 的 ops 写 `value: 3`，描述说「接下来 2 次行动」**
   - 这不是错：出牌本身会消耗一次行动计数，`afterPlayerAction()` 立即减 1，净值正好 2 次。同理 `deerstalker` 的 `value: 2` 在运行时按 `value + 1` 处理后再减 1。
10. **「死亡恐惧」的描述是「每有一个受伤、倒地或已死亡的人类」**
    - 实际 `fearWave` 的层数包含 `state.kills`（所有击杀，含警察击杀）；在一般局内差别不大，但严格说与「人类」不完全一致。
11. **平衡面板的开关下拉缺少 `stealthNext`**
    - 「静止隐身」的 ops 使用 `flag: stealthNext`，但 `effectCatalog.ts` 的 `FLAG_OPTIONS` 没有收录它；面板渲染下拉时找不到匹配值，会默认显示第一个选项 `phoneCut`。不碰这个下拉不会改数据，但一旦重选就会把卡改错。

## 八、肉鸽猎杀（独立模式）

入口在主菜单的模式卡片/按钮里（「肉鸽猎杀」），和契约猎杀、自由猎杀并列；有进行中的 run 时按钮会显示当前层数，可以继续。

### 8.1 一局肉鸽怎么开始
- **牌组**：从当前杀手的可用卡池里随机抽 12 张（`rollRogueDeck`，卡池混洗）。
- **配件**：只在该杀手的 3 件配件里随机抽 2 件（`rollRogueAccessories`，配件不混）。
- **猎场规则**：随机 1 条平时对局里不会出现的规则（`ROGUE_BUFFS`），例如每回合行动点 +1 / 幸存者生命 +1 / 开局警报 +20。

### 8.2 层与奖励
- 通一层（契约主目标完成并胜利）→ 弹出三选一：2 张随机卡牌 + 1 条未拥有的猎场规则；
- 选中后层数 +1、奖励写进 run，然后用同一套牌组和配件（可能新增卡）开下一层；
- 层数越高：开局警报 +(层数-1)×6，契约回合 -(层数-1)；
- 失败：本轮进度清空，回到大厅；主界面会显示当前层数，方便重开。

### 8.3 现在只有 9 条规则
| id | 名称 | 效果 |
| --- | --- | --- |
| ap_up | 肾上腺素 | 每回合行动点 +1 |
| ap_down | 负重前行 | 每回合行动点 -1 |
| tough | 皮糙肉厚 | 所有幸存者生命 +1 |
| alarm_up | 风声鹤唳 | 开局警报 +20 |
| alarm_down | 悄无声息 | 开局警报 -15 |
| short_contract | 时限收紧 | 契约回合 -3 |
| loot | 搜刮者 | 开局战利品 +3 |
| frenzy | 杀戮本能 | 开局杀戮值 50 |
| fear | 恐惧弥漫 | 幸存者开局恐惧 +20 |

要加新规则：在 `src/game/rogue.ts` 的 `ROGUE_BUFFS` 里加一条 `{ id, name, desc, apply(state) }` 即可，`apply` 直接改 `GameState`（比如 `state.maxEnergy += 1`）。加完跑 `npm run check`，不用改别的地方。

### 8.4 配件拥有方式
配件现在是**买过即永久拥有**：装配界面显示「已拥有 / 未拥有」，血点只用于解锁未拥有的配件，出发前从已拥有里挑最多 2 件，不再消耗。

## 九、血网升级 / 角色等级 / 公共卡池

### 9.1 用血点买等级（没有经验）
- 主菜单「血网升级」→ 顶部选杀手（每位杀手等级独立）。
- 升一级的价格：**50 +（当前等级 - 1）× 15 血点**，点按钮立刻扣血点、等级 +1。
- 血点想给谁花就给谁花：你可以一直玩迈尔斯，却把血点全砸在护士身上。
- 等级到 100 自动**转生**：等级回到 1，转生数 +1，之后继续买（没有上限）。

### 9.2 血网三选一
主菜单点「血网升级」打开，三条随机路线：

| 路线 | 效果 |
| --- | --- |
| 配件 | 该杀手的专属配件 **库存 +1**（带入猎场会扣 1） |
| 卡牌 | 永久解锁一张该杀手池子里还没解锁的卡 |
| 血点 | 直接加 40–70 血点 |

### 9.3 公共卡池（每 30 级）
- 每位杀手按「累计等级 = 转生 × 100 + 当前等级」计算；**每 30 级**把自己的一张专属卡放进公共池。
- 公共池的卡所有杀手都能在牌组编辑器里构筑（例：迈尔斯 90 级 → 护士也能带迈尔斯的 3 张专属卡）。
- 共享结果由 `syncSharedCards()` 在每次读档/升级时自动重算，存在存档的 `sharedCards` 里。
