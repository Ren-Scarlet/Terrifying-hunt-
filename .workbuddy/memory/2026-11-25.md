# 2026-11-25 · 夜猎档案：猎杀流程重做

## 这一轮做了什么（commit 434c882，已推送）

- **生死分档**：`hp 2|1|0`，`damagePerson` 只推进一档；`executePerson` 要求 `hp<=0`；`rescuePerson` 倒地→受伤；`BLEEDOUT_TURNS = 3`。
- **进门窗口**：`npcOnPlayerEnter` 不再调 `fleeAway`，只把 intent 设成 `flee` + 日志，真正的移动留到 `npcTurn`。这是可玩性的关键——否则一进门人就瞬移到隔壁，玩家没有出手机会。
- **六原型**：`ArchArchetype = alert|defiant|caller|rescuer|hider|brave` + `actByArchetype()` 分派；`shout()` 只有真的喊醒别人才 `addAlarm`（原来每次逃跑都 +3，警戒永远压不住）。
- **团队警戒** `state.alarm` 0–100，满即判负；`arrestThreshold = 5 + mission.targetCount`。
- **通缉**：`addWanted` 会写 `heatTurn`；`killPerson` 只有"有目击者"才加；`endTurn` 里 `heatTurn !== turn` 就 −1 降温；`policePhase` 有 `policeLock` 两回合缓冲才逮捕，`policeNextStep` 只追 `heatTurn >= turn-1` 的新鲜现场。
- **逃跑链路修复**（本轮重点）：`wantsToLeave()` = 在后院 && (intent escape/flee 或 alert≥35)。`escapePhase` 和 `npcTurn` 都用它；`fleeAway` 里 `mayExit` 控制谁能跑进后院；低警觉闲逛过滤掉 `ESCAPE_ROOMS`——原来闲逛会随机走进后院直接翻篱笆，玩家不动作也会有人逃走。
- **12 间房 + 后院**，出生点距入口 ≥2 步。
- **三层迷雾**：`explored[]` / `scouted{}` / `isRoomVisible()`，人物留 `lastSeenRoom/lastSeenTurn` + `ghost-chip`。
- **平衡工作台**：`src/game/tuning.ts`（localStorage `night-hunt-tuning-v2`）+ `src/ui/admin.ts`，主菜单「平衡调整」。

## 平衡验证方法（重要）

`.tmpshot/sim2.ts`（随机乱点）、`.tmpshot/sim3.ts`（会打的玩家，`SIM_MODE=brute|stealth`）各 104 局。
esbuild 打包成 `.mjs` 后 `node` 跑。**模拟玩家必须先移动再出牌**，否则永远在新房间才动手，数据会严重失真（曾因此得出"击杀 0.33/局"的错误结论）。

最终数字：乱点 10% 胜率、有章法 25–32%，失败分布落在 警戒/通缉/天亮/逃离 四类。

## 踩过的坑

- `shot6/shot7.mjs` 里点 `.room` 不会移动——可点元素是房间内的 `.room-hit` 按钮。测试脚本点错会得出"游戏不能移动"的错觉。
- `createGame(deck, mission, killer)` 第二个参数是 Mission 对象，传字符串会让 `mission.kind` 变 undefined，胜利判定永不触发。
